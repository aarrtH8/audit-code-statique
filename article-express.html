J'ai audité le code d'Express en statique : 65 alertes, dont 60 fausses

(méthode, chiffres réels, et pourquoi je les publie)

J'ai écrit un auditeur statique qui lit un dépôt GitHub public et sort chaque motif : . Pour l'étalonner, je l'ai lancé sur expressjs/express — le framework Node le plus installé au monde, maintenu par des gens très compétents.

Sortie brute : 65 constats sur 60 fichiers lus, dont 0 critique, 3 élevés, 2 moyens, 60 faibles.

Voilà le point qui compte : la plupart sont du bruit, et le dire est plus utile que de te vendre 65 vulnérabilités.

Ce que les 5 constats non-triviaux veulent dire

Les 3 « élevés » et les 2 « moyens » tombent dans des catégories classiques :

  • eval / new Function : Express en contient pour la compilation de templates et pour res.render. Dans ce contexte, l'entrée n'est pas arbitraire — c'est du code de l'application elle-même. Un scanner qui crie « RCE » ici se trompe.
  • innerHTML : utilisé dans le moteur de vues pour insérer du HTML déjà rendu par l'application. Le risque réel dépend du chemin de la donnée, que le motif seul ne voit pas.
  • concaténation de commande / chaîne de connexion : présentes dans les scripts de test et la configuration d'exemple, pas dans le chemin de production.

Autrement dit : un motif n'est pas une vulnérabilité. C'est une adresse. Il faut encore ouvrir la ligne et poser une seule question : une entrée externe peut-elle l'atteindre ?

Les 60 « faibles »

Ce sont presque tous des URLs http:// dans les fichiers de test, de documentation et de fixtures. Utile à savoir : si l'un d'eux était dans du code de production, ça vaudrait la peine de le corriger. Dans un fichier de test, ça n'a pratiquement aucun impact.

Ce que ça dit de l'audit statique en général

Un outil qui te sort 65 lignes sans hiérarchie te fait perdre ta journée. Un outil qui te dit « voici 5 endroits où regarder en priorité, voici pourquoi les 60 autres sont probablement du bruit, et voici les 3 questions à te poser sur les 5 premiers » te fait gagner une demi-journée.

La valeur d'un audit n'est pas dans le nombre d'alertes. Elle est dans le tri.

La limite honnête

Cet outil analyse par motifs. Il ne confirme aucun impact réel. Il ne regarde pas tes dépendances, ta configuration serveur, ni ton infrastructure. Il ne remplace pas ton jugement sur ton propre code.

Ce qu'il fait bien : te donner les adresses à visiter, dans le bon ordre, en marquant clairement ce qui est crédible et ce qui est du bruit.

Si tu veux le deuxième passage — celui qui croise les motifs avec le contexte d'appel, écarte les faux positifs et priorise pour de vrai — c'est là que je travaille. Prix sur devis, convenu avant de commencer.
