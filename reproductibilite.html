Pourquoi c'est le point qui compte

Un rapport d'audit sans reproductibilité est une affirmation, pas une preuve. Si je ne peux pas relancer mon analyse et retomber sur les mêmes chiffres, alors vous n'avez aucun moyen de savoir si ce que vous payez décrit votre code ou une approximation.

Concrètement : relancer l'analyse donne le même résultat. Vous pouvez donc reproduire ce que j'ai livré avant de payer quoi que ce soit.

Le faire vous-même

L'outil est public. Téléchargez-le, lancez-le sur votre dépôt, comparez avec ce que je vous envoie :

# Récupérer l'auditeur
curl -L -o audit-sarif.mjs https://aarrth8.github.io/audit-code-statique/tools/audit-sarif.mjs

# Analyser votre dépôt
node audit-sarif.mjs https://github.com/votre-compte/votre-projet --out audit.sarif

# Vérifier la reproductibilité vous-même (deux passes, comparaison)
node tools/audit-reproductible.mjs https://github.com/votre-compte/votre-projet

L'auditeur n'a aucune dépendance, ne fait aucun appel réseau une fois le dépôt récupéré, et n'exécute jamais votre code.

Les limites, écrites avant que vous payiez. Analyse statique par motifs : votre code n'est jamais exécuté, ce n'est pas un test d'intrusion. Les fichiers de test, exemples et dépendances sont exclus. Chaque entrée est un constat, pas une vulnérabilité confirmée — un arbitrage reste nécessaire pour écarter les faux positifs. Je ne garantis aucune absence de faille.

Vérifier ce que vous recevez

Chaque livrable porte une empreinte SHA-256 du rapport et de l'arborescence source analysée. Si la valeur que vous recalculez diffère, le document a été modifié après livraison — dans ce cas, ne l'acceptez pas.

sha256sum -c RAPPORT.html.sha256    # doit afficher : OK
