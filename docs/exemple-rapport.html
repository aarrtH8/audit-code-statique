Le rapport — 7 constats, dont 6 graves

Élevée — secret ou identifiant en dur
app.js:6
const API_KEY = "CLE_FACTICE_DE_DEMONSTRATION_PAS_UNE_VRAIE_CLE";

Une clé committée doit être considérée comme compromise dès qu'elle a été poussée, même si vous la supprimez au commit suivant : elle reste dans l'historique. Correctif : variable d'environnement, puis rotation de la clé.

Élevée — secret ou identifiant en dur
app.js:11
user: 'root', password: 'motdepasse-de-demo-factice', database: 'customers'

Deux problèmes sur une seule ligne : un compte root là où un compte applicatif restreint suffirait, et un mot de passe dans le code source. Une fuite du dépôt donne un accès complet à la base.

Élevée — requête SQL construite par concaténation
app.js:17
db.query("SELECT * FROM users WHERE id = " + id, (err, rows) => {

id provient de req.query.id. Une valeur comme 1 OR 1=1 retourne toute la table. Correctif : requête préparée avec un paramètre lié.

Élevée — requête SQL construite par concaténation
app.js:25
const q = "SELECT * FROM users WHERE email = '" + email + "'";

Même défaut sur une route d'authentification : c'est le pire endroit pour laisser une injection. Une apostrophe dans l'entrée suffit à casser la requête, et bien plus avec une entrée choisie.

Élevée — mot de passe comparé ou stocké en clair
app.js:27
if (rows.length && rows[0].password === password) {

La comparaison directe suppose que la base stocke les mots de passe lisibles. Une fuite de base = tous les comptes compromis, sans effort de l'attaquant. Correctif : hachage lent (bcrypt, argon2) et vérification dédiée.

Élevée — jeton d'authentification dérivé d'une donnée publique
app.js:28
res.json({ ok: true, token: Buffer.from(email).toString('base64') });

Le « jeton de session » est l'email encodé en base64 : n'importe qui peut en fabriquer un pour n'importe quel compte, sans connaître le mot de passe. Correctif : jeton aléatoire cryptographiquement sûr, stocké côté serveur.

Moyenne — erreur interne renvoyée au client
app.js:18
if (err) { res.send(err); return; }

Renvoie l'objet d'erreur complet à l'appelant, ce qui peut exposer le schéma de la base et les chemins internes. Correctif : journaliser côté serveur, renvoyer un message générique et un identifiant de corrélation.

Ce que ce rapport ne prétend pas

Il ne dit pas « votre application est vulnérable ». Il dit : voici des motifs à vérifier, à ces lignes précises. La nuance compte. Un outil statique ne prouve pas qu'une faille est exploitable ; il prouve qu'un humain doit regarder. C'est exactement ce pour quoi vous payez.
